# Feishu2PPT 中文使用说明

Feishu2PPT 的工作方式是：在飞书里整理内容，先生成可审查的页面计划，再渲染为可编辑的 PowerPoint。它不会直接改写原飞书文档，也不会在没有确认页面计划时自动生成最终 PPT。

## 1. 安装与环境

### macOS / Linux

\`\`\`bash
bash scripts/install.sh
python3 scripts/doctor.py
\`\`\`

### Windows

\`\`\`powershell
powershell -ExecutionPolicy Bypass -File scripts/install.ps1
python scripts/doctor.py
\`\`\`

需要的基础环境：

- Python 3.11 或更高版本。
- Node.js 与 npm，用于运行官方 \`@larksuite/cli\`。
- OfficeCLI，用于生成、校验和截图 PPTX。
- \`ffmpeg\` 可选：只有文档内有视频并且需要生成视频首帧海报时才需要。

首次使用飞书时，命令行可能会打开浏览器进行授权。登录、验证码和权限确认必须由本人完成；凭据保留在飞书 CLI 自己的凭据存储中，不写入本 Skill。

## 2. 在飞书里怎么写

建议按下面的层级组织：

\`\`\`text
文档标题：深圳项目月度营销复盘

# 01 本月核心判断
## 成交增长来自有效到访提升
本月到访量连续三周增长，客户结构同步改善。
- 直播贡献了新增客资，但到访转化仍需要重点复盘。
- 下一阶段先拆开管理留资到到访的流失环节。

# 02 数据表现
## 4 月以后到访与认购同步加速
图表：折线图
结论：4 月以后，到访与认购同步加速。
来源：示例销售日报，统计截至 2026-08-01。
| 月份 | 到访 | 认购 |
|---|---:|---:|
| 1月 | 62 | 18 |
| 2月 | 75 | 22 |

# 03 执行方案
## 三步把留资推进到到访
1. 当天确认客户预算与购房时间。
2. 24 小时内发送项目对比与看房路线。
3. 到访后当天回收异议并进入复访。
\`\`\`

结构约定：

- 文档标题生成封面。
- 一级标题生成章节页。
- 二级标题生成一页 PPT。
- 三级标题用于页内分组。
- 图片、视频、表格要放在对应的二级标题下面，不要全部堆到文档末尾。
- 精确数据用表格；趋势、排名、占比和转化链路用图表。

可用的页面指令包括：\`版式：表格\`、\`图表：柱状图\`、\`图表：条形图\`、\`图表：折线图\`、\`图表：面积图\`、\`图表：环形图\`、\`图表：瀑布图\`、\`图表：漏斗图\`、\`图表：散点图\`、\`图表：直方图\`、\`图表：矩形树图\`、\`图表：雷达图\`、\`图表：组合图\`、\`结论：...\` 和 \`来源：...\`。

## 3. 生成页面计划

### 真实飞书文档

\`\`\`bash
python3 scripts/run.py plan \\
  --doc "https://example.feishu.cn/docx/xxx" \\
  --theme data_journalism \\
  --workdir "/绝对路径/深圳项目月报-files"
\`\`\`

### 不登录飞书的本地演示

\`\`\`bash
python3 scripts/run.py plan \\
  --source-xml examples/sample-feishu.xml \\
  --workdir /tmp/feishu2ppt-demo-files
\`\`\`

计划阶段会生成：

- \`source.xml\`：飞书原始结构快照。
- \`assets/\`：图片、视频和其他素材。
- \`deck.json\`：可以人工调整的页面计划。
- \`plan-preview.md\`：按页查看的快速预览。
- \`plan-report.json\`：结构、素材、图表和占位符检查结果。

先看 \`plan-preview.md\` 和 \`deck.json\`，确认主题、页数、章节、页面标题、版式、图表和素材分配。不要跳过这一阶段直接渲染。

## 4. 渲染可编辑 PPT

确认页面计划后执行：

\`\`\`bash
python3 scripts/run.py render \\
  --plan "/绝对路径/深圳项目月报-files/deck.json" \\
  --output "/绝对路径/深圳项目月报.pptx" \\
  --approve-plan
\`\`\`

渲染器默认使用微软雅黑。现有 PPT 会先保存为 \`.bak\`，新文件只有在校验通过后才替换最终输出。

## 5. 交付前检查

\`\`\`bash
officecli validate "/绝对路径/深圳项目月报.pptx"
officecli view "/绝对路径/深圳项目月报.pptx" issues --json
officecli view "/绝对路径/深圳项目月报.pptx" screenshot --page 1-20 --grid 4 --out "/绝对路径/深圳项目月报-preview-grid.png"
\`\`\`

正确的验收顺序是：先确认 \`validate\` 通过，再确认 issues 为 0，最后检查完整缩略图和正文密集页。进程退出码正常或 PPT 能打开，都不能替代视觉检查。

## 6. 三个可复用演示案例

### 案例 A：深圳楼盘月度营销复盘

适合：月报、销售复盘、直播获客复盘。

推荐主题：\`data_journalism\`。

飞书文档结构：

\`\`\`text
# 01 核心判断
## 成交增长来自有效到访提升
三条业务判断。

# 02 数据表现
## 到访与认购同步加速
图表：折线图
结论：4 月以后，到访与认购同步加速。
来源：销售日报。
表格：月份、到访、认购。

# 03 下一步
## 先解决留资到到访的流失
三步执行动作。
\`\`\`

预期页面：封面、核心判断章节页、判断页、数据章节页、折线图页、下一步章节页、执行页。图表会保持可编辑，右侧显示业务结论。

仓库内对应的本地示例是 \`examples/sample-feishu.xml\` 和 \`examples/showcase-plan.json\`。

### 案例 B：房地产项目提报

适合：开发商提报、楼盘定位、单盘直播方案、广告公司内部启动会。

推荐主题：\`realestate_gold\`、\`architectural_sand\` 或 \`swiss_monocle\`。

飞书文档结构：

\`\`\`text
# 01 项目判断
## 这个项目真正要解决的是改善客户的决策犹豫
项目现状、客户抗性、竞争替代。

# 02 核心策略
## 用三条内容线把项目优势变成可验证的生活场景
图片：项目实景或区位图。
三条内容线。

# 03 执行样例
## 从短视频到直播间的内容承接
视频：样片或直播片段。
流程、脚本节点和销售承接方式。
\`\`\`

预期页面：章节转场、单一判断页、图文并置页、图片画廊页、流程页和案例页。图片放在对应内容页，不会被集中到最后一页。

### 案例 C：团队培训课件

适合：WorkBuddy / AI 工具培训、销售培训、直播术语培训、内部 SOP。

推荐主题：\`vercel_minimal\`、\`apple_keynote\` 或 \`executive_navy\`。

飞书文档结构：

\`\`\`text
# 01 先建立共同语言
## 直播间的三个关键指标
### 曝光
### 停留
### 留资

# 02 再按流程练习
## 一次直播复盘怎么做
图表：漏斗图
结论：先找到流失最大的环节，再决定优化动作。
表格：环节、人数、转化率。

# 03 现场演练
## 从一个楼盘问题写出一条口播
视频：示例视频。
练习要求和交付标准。
\`\`\`

预期页面：指标卡、流程页、漏斗图页、视频素材页和练习页。视频可在 Office/编码器支持时作为可播放媒体，同时生成首帧海报帮助读者识别内容。

## 7. 主题怎么选

- 通用提报：\`vercel_minimal\`。
- 房产和高端项目：\`realestate_gold\` 或 \`architectural_sand\`。
- 数据复盘：\`data_journalism\`。
- 经营汇报：\`executive_navy\`。
- 产品或 AI 工具发布：\`apple_keynote\`。

主题、版式和图表是三层独立选择。先决定这页要让读者得出什么结论，再选版式，最后才选颜色和图表，不要把一套主题当成整份 PPT 的内容逻辑。

## 8. 常见边界

- 只给飞书链接但没有授权：只能停在授权提示，不能假装已读取文档。
- 飞书内嵌表格或多维表格：先通过对应飞书能力读取数据，再写入页面计划。
- 原文内容太多：系统会自动拆页，但需要复核分页后的结论是否仍然完整。
- 视频没有 \`ffmpeg\`：仍可保留视频素材，但不能保证生成可见首帧海报。
- Windows 安装器已经提供，但 Windows 的完整验收仍需在 Windows 机器上执行，不把 macOS 的结果写成 Windows 已验证。
